# Turn wire format: two-phase Subgraph with server-parsed inline Citations over NDJSON

The Scene must highlight progressively while the Answer streams, yet the retrieval pipeline makes one LLM call whose validated used ids are only known at the end. We resolve this with a **two-phase Subgraph**: Retrieval sends the candidate Subgraph first so the Scene can pre-dim it, Citations arrive inline as the text streams and light Nodes one by one, and the final event carries the validated used ids so the Scene drops anything never cited. Transport is a streamed `fetch` response body of newline-delimited JSON, because a pasted job description needs a POST body and `EventSource` is GET-only.

## Request

`POST /api/turn`, JSON body validated by `packages/schema`:

| Field | Type | Notes |
|---|---|---|
| `prompt` | string | required |
| `previousUsedIds` | Node and Edge ids | optional; extra seeds for multi-turn continuity |
| `history` | last three Turns of Prompt and Answer text | optional; Retrieval enforces the token budget |

The endpoint is stateless. The client holds the conversation.

## Events

One JSON object per line, a tagged union validated by `packages/schema`, in this order:

| Event | Payload | When |
|---|---|---|
| `turn-started` | `turnId`, `mode` ∈ `match \| entity \| hybrid` | first |
| `subgraph` | candidate Node ids and Edge ids, seeds flagged | second, before any text |
| `text` | Markdown delta with Citation markers stripped | streaming |
| `citation` | Node id or Edge id, ordinal index | streaming, ordered relative to `text` |
| `followups` | suggested next Prompts | after text |
| `turn-finished` | validated used Node and Edge ids, token usage | last |
| `error` | tagged error, `retryable` flag | terminal, replaces `turn-finished` |

## Citations

The LLM writes inline markers `[[<id>]]` in the Answer. Node ids are `<type>/<slug>` (ADR 0001). Edge ids are `<source id>--<edge type>--><target id>`, generated by the indexer, for example `project/ingestion--uses-->skill/effect`; the prompt template shows every Edge as its id plus its note so the model copies rather than invents. Retrieval parses markers out of the text deltas server-side, validates each id against the candidate Subgraph, and emits a `citation` event in stream order. A citation's position is its ordinal: the client inserts a numbered chip at the point in the text where the event arrived. Character offsets were rejected because Markdown normalisation on the client invalidates them.

## Cancellation and errors

A new Prompt mid-stream aborts the `fetch` via `AbortController`; the server interrupts the Effect fiber. Errors are one terminal `error` event with no automatic retry; the Answer panel shows it inline and keeps the previous Turn's Highlight.

## Considered and rejected

- **Wait for the end and send the Subgraph with the structured output.** Rejected: the Scene has nothing to do during the slowest part of the Turn.
- **Two LLM calls (ids first, then the Answer).** Rejected: doubles cost and latency for a signal the two-phase approach gets for free.
- **Tool calls per Citation.** Rejected: providers batch tool calls and they break the text flow.
- **Server-Sent Events.** Rejected: GET-only in the browser API, and `Stream.toReadableStreamEffect` already yields the body.
- **Server-side session for history.** Rejected: statelessness keeps the Cloudflare deployment trivial.
